# Insurance & Claims Management System

DBMS course project, MNNIT Allahabad (B.Tech CSE, 2026-27). MySQL 8.0.46 (InnoDB) + FastAPI + plain HTML/JS + scikit-learn.

## One-time setup (Windows)

1. `pip install -r requirements.txt`
2. Copy `.env.example` to `.env` and choose a password for `DB_PASSWORD`. Put the same password in place of `CHANGE_ME` in `db/00_setup_user.sql`.
3. Create the app user and databases (asks for the MySQL root password):
   ```
   & "C:\Program Files\MySQL\MySQL Server 8.0\bin\mysql.exe" -u root -p -e "source <full path>/db/00_setup_user.sql"
   ```
   Use forward slashes in the path.
4. Build the database: `python scripts/build_db.py`, then train the model: `python ml/train.py` (or run `python scripts/run_everything.py` for both plus all evidence and tests).

## Everyday commands (from the project root)

| What | Command |
|------|---------|
| Rebuild the database from scratch (schema, triggers, procedures, views, seed, indexes) | `python scripts/build_db.py` |
| Regenerate ALL report evidence + run tests | `python scripts/run_everything.py` |
| Start the web app | `python -m uvicorn api.main:app --port 8000`, then open http://127.0.0.1:8000 |
| API documentation | http://127.0.0.1:8000/docs |
| Tests only (uses the separate `insurance_test` DB) | `python -m pytest` |
| Retrain the fraud model | `python ml/train.py` |

`db/run_all.sql` does the same rebuild through the mysql CLI (`cd db` then `mysql -u insurance_app -p < run_all.sql`, in cmd).

## Layout

| Path | Contents |
|------|----------|
| `db/01_schema.sql` | 15 tables in BCNF (incl. `pincode` and the `fraud_model` registry), PK/FK/UNIQUE/CHECK constraints |
| `db/02_triggers.sql` | BR1-BR10 + product cover check (12 triggers) |
| `db/03_procedures.sql` | 3 functions, 16 procedures (atomic workflow, NEEDS_INFO, premium lifecycle, model registry) |
| `db/04_views.sql` | 10 views incl. `v_claim_features` for ML and the customer/provider directories |
| `db/05_seed_data.sql` | generated by `scripts/generate_seed.py` (seed 42, synthetic) |
| `db/06_indexes.sql` | secondary indexes |
| `db/07_queries.sql` | DML, joins, subqueries, ROLLUP, windows, CTEs, INTERSECT/EXCEPT, 8 reports |
| `db/08_rule_demos.sql` | every rule and transaction demo, expected errors included |
| `api/` | FastAPI app (`main.py`), generic CRUD (`crud.py`), reports, pooled DB access + error mapping (`db.py`) |
| `web/` | single-page front end |
| `ml/` | `train.py` (training/evaluation), `fraud.py` (shared features + scoring) |
| `tests/` | pytest suite (30 tests) |
| `docs/Project_Report.pdf` | project report (Word version alongside) |
| `docs/outputs/` | saved evidence: query/demo output, EXPLAIN before/after, concurrency, ML metrics + charts, pytest |

## Evidence files for the report

- `docs/outputs/07_queries.txt`: every query in 07 with its result
- `docs/outputs/08_rule_demos.txt`: BR1-BR10, CHECK/FK/UNIQUE errors, atomic rollback, SAVEPOINT, lapse/re-activation
- `docs/outputs/explain_before_after.txt`: real `EXPLAIN ANALYZE` output with and without indexes
- `docs/outputs/concurrency_demo.txt`: concurrent approval (row lock) and deadlock (errno 1213)
- `docs/outputs/ml/`: `metrics.json`, `train_log.txt`, ROC / PR / confusion-matrix / importance charts
- `docs/outputs/pytest.txt`: test run

## Notes

- Data is synthetic and generated with a deliberate fraud signal. ML metrics show the pipeline works, not real-world accuracy.
- The reference "today" for the seed is 2026-11-04. Overdue and expiry figures are computed against `CURRENT_DATE`, so they shift a little on later days.
- InnoDB cascaded FK actions (`ON DELETE CASCADE/SET NULL`) do not fire triggers.
- Risk bands: HIGH = score >= the active model's threshold (stored in `fraud_model`), MEDIUM = at least half of it.
- The rule demos (08) and the concurrency demo delete their own rows when they finish, so reports and ML training see only seed data.
- Premium instalments can only be changed through `sp_pay_premium` / `sp_generate_instalments`; generic CRUD on payments is read-only (HTTP 405).
